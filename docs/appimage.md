# AppImage candidates

The package version is **1.0.0**, prepared for the first stable release. Building a candidate does not create a tag, publish a release, or change repository visibility. Candidate builds run on temporary GitHub Actions runners; no local build-tool installation is required or authorized by this workflow.

## Build and retrieve a candidate

The [AppImage workflow](../.github/workflows/appimage.yml) runs when `main` or a `build/**` branch is pushed. It can also be run with **Actions → AppImage candidate → Run workflow**, selecting the reviewed revision. Candidates support public and private repositories. The canonical repository is [Shin-Aska/QPushBulletDesktop](https://github.com/Shin-Aska/QPushBulletDesktop), which the owner has made public. There are no PR/fork triggers, and the candidate job has only `contents: read` and `actions: read` (for the pinned baseline download).

The workflow installs OS dependencies only on its temporary Ubuntu 24.04 runner. It verifies the SHA256 of an exact official CPython 3.14.4 archive, seeds its temporary tool cache, and selects it through a commit-pinned `setup-python`. Separate environments run the full repository regression suite and freeze only the production desktop/web/MCP dependencies. Python distributions use exact version and SHA256 pins with `--require-hashes --only-binary=:all:`. SQLCipher must come from the pinned binary wheel; the workflow does not substitute Ubuntu's SQLCipher development package or build a different encryption engine.

PyInstaller 6.22.3 builds a standalone directory. The AppDir contains that executable/runtime, application resources and metadata, Qt plugins/libraries, migrations, SQLCipher and its native dependencies. The builder verifies an exact official AppImage type-2 runtime and appends a SquashFS filesystem using the runner's recorded `squashfs-tools` version. Tool URLs and hashes live in [toolchain.json](../packaging/toolchain.json); resolved Python and OS package versions are recorded in each build. The pinned release inputs and captured runner inventory improve auditability; the mutable Ubuntu apt repositories and hosted runner image mean this is not a claim of bit-for-bit reproducible builds.

A successful run uploads one candidate artifact named `pbdesk-appimage-<commit>`, retained for **two days**. Failure evidence is retained for one day. Download the artifact before it expires; repeated large candidates count toward the account's Actions storage quota. This workflow creates no cache and enables no paid usage. The bundle contains:

- `pbdesk-1.0.0-x86_64.AppImage`
- `pbdesk-1.0.0-source.tar.gz`, containing the actual selected working-tree source/build inputs, with private profiles and non-build historical `design/` galleries excluded
- `pbdesk-1.0.0-build-info.json`, including source revision/status, input hashes, dependency/tool inventory, runtime identities and evidence references
- `pbdesk-1.0.0-licenses.tar.gz`, containing actual available wheel/CPython/project license texts and source accounting
- `pbdesk-1.0.0-corresponding-source.json` and numbered `pbdesk-1.0.0-corresponding-source-*.tar` parts, with matching applicable source, Ubuntu patches and rebuild material
- `smoke-evidence.json`, `regression-results.xml`, `release-acceptance.json`, baseline selection and final readiness evidence
- `pbdesk-1.0.0-SHA256SUMS` covering the complete bundle

For the downloaded AppImage, run `sha256sum --check --ignore-missing pbdesk-1.0.0-SHA256SUMS` and require its line to report **OK**. For a complete downloaded bundle, use `sha256sum --check pbdesk-1.0.0-SHA256SUMS` without `--ignore-missing`. The source archive uses the bytes actually frozen, including tracked modifications and nonignored new inputs; it does not blindly archive an older commit. The clean checkout binds those inputs to the recorded commit. The source ledger maps every bundled ELF to its actual PyInstaller input and wheel, official CPython archive or Ubuntu package provenance. Applicable corresponding source includes original archives, downstream patches and build recipes; permissive components retain actual notices and source references. The ledger explicitly states the upstream launcher's unrecorded permissive Alpine package revisions. Bit-for-bit reproducibility is not claimed.

## Launch and persistent processes

Mark the AppImage executable and launch it directly. FUSE-capable desktop sessions use the normal type-2 mount; `APPIMAGE_EXTRACT_AND_RUN=1 ./pbdesk-1.0.0-x86_64.AppImage` is the supported extraction fallback when FUSE is unavailable. Launching downloads and installs nothing.

`AppRun` invokes the frozen executable's bootstrap. Before application dispatch, it validates the bundled manifest and copies the complete runtime into a private `0700` cache below `$XDG_CACHE_HOME/pbdesk/runtimes/<runtime-id>` (normally `~/.cache/pbdesk/runtimes/`). It validates file SHA256 values/modes and in-tree symlink targets, then executes the cached runtime. Core, optional web host, restart helpers and later desktops use this surviving runtime after the original mount disappears. Existing runtimes are deliberately retained because another process may still use them; do not remove a runtime directory while pbdesk services are running. Replacing the AppImage starts a separately identified runtime.

The application directory comes from the real outer AppImage path (`REALAPPIMAGE` when supplied by an integration, otherwise `APPIMAGE`), rather than its mounted or cached interpreter directory. The default database remains `pbdesk.sqlite3` beside that file. The containing directory must be writable. Explicit `PBDESK_APPLICATION_DIR` and `PBDESK_STATE_DIR` overrides retain their normal meaning. Bootstrap state and credential references stay in the private state directory. Do not place candidate executables beside the owner's real database for smoke testing.

The frozen executable supports normal desktop arguments and these dispatch selectors: `--core`, `--web`, `--mcp`, `--admin`, `--diagnostics`. `--admin install-service` is an explicit operation and writes a persistent original-AppImage command; candidate builds do not install or start a user service.

## Verification and remaining release gates

CI builds the immutable AppImage and source/notices material, smoke-tests the actual artifact from outside the source checkout with `PYTHONPATH` and `PYTHONHOME` removed, then runs the full source regression suite. It also verifies actual lower-version replacement, retained encrypted data/settings/references, recovery into a fresh fixture wallet entry and interrupted plaintext migration/resume. Successful upload requires every stage and checksum verification to pass. [The external smoke harness](../packaging/smoke.py) uses synthetic temporary profiles, its own private session bus and fake KWallet, and an isolated Xvfb display. It exercises the bundled SQLCipher/FTS5, first-run desktop and packaged process behavior, and records exactly which checks completed. It never uses the owner's live profile, wallet, providers or systemd services. A successful workflow is necessary evidence; source/helper tests alone do not establish that an AppImage builds or runs.

Ubuntu/Xvfb evidence does not certify native KDE Plasma 6 Wayland, real KWallet authorization, notification/tray integration, suspend/resume, or existing-profile upgrades on Kubuntu 26.04. Owner feedback supplies basic native launch/product acceptance. Those additional integrations remain documented scope limitations in [the release plan](release-plan.md), without implying they were all exercised by isolated CI fixtures.

The initial upgrade baseline is the independently pinned 0.1.0 candidate from source `15c65759ce73b9dd59448b2a46a6a1fa0ab702ca`, with AppImage SHA256 `673c2b2d9dc08db2a4e720cba8d43be62b35dbd2e954e931dda6e0c37e112643`. Later versions select the highest published non-prerelease stable version strictly below the target, pinning its tag/source and GitHub asset SHA256. After a version is published, ordinary same-version candidates use that published artifact for trial replacement checks and remain `candidate: true` / `final_release_ready: false`; they do not depend on the expiring initial Actions artifact. Same-version replacement or an arbitrary older artifact cannot close the strict tag upgrade gate.

Readiness is derived after testing. The verifier measures the actual outer AppImage hash, inner runtime identity/version, old/new source and material identities, and concrete outcomes. The external finalizer rechecks source tar bytes, the source ledger anchored inside the sealed runtime, every actual ELF, acceptance evidence, smoke and regression results. It updates only the external build-info/readiness sidecars and asset checksums; the tested image stays unchanged. `packaging/release-readiness.json` records explicit publication/owner acceptance policy, not unsupported completion flags. See [the acceptance procedure](release-acceptance.md).

The final path requires a deliberate stable `v1.0.0` or later tag exactly matching the package version, a public repository, authorized policy and a fully validated bundle. Only the separate release job receives `contents: write`; it independently checks the complete evidence and creates an owner-reviewed **draft**. Publishing that draft remains a separate deliberate operation. Candidates do not change visibility or publish a release.

Qt/PyQt and native components retain their licenses. Release assets provide actual notices and applicable matching sources, including Qt translations and static libfuse patches. Extract all source tar parts together and follow [the rebuild/library-replacement instructions](../packaging/REBUILDING.md). Modified libraries and manifests require no secret, upstream signature or identical compiler output.
