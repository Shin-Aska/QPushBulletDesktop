Outgoing note/link/SMS uses explicit `provider_plaintext`: Pushbullet can process the content, and SMS carrier delivery is not end-to-end encrypted. The incoming E2E password does not silently enable an undocumented outgoing E2E mode. Native approval requires acknowledgment for the exact displayed action; MCP cannot grant that acknowledgment or approve its own request.

A notification preview is not an addressable SMS conversation. The native compose form never infers a telephone number from notification text; SMS requires an explicit E.164 recipient and a selected SMS-capable device. Active device registration is shown without claiming current online connectivity. Pushbullet acceptance is not confirmation of delivery, and uncertain sends are not automatically retried.

All clients use the same core state and outbox pipeline. They never open SQLite, call Pushbullet, read provider secrets, decrypt provider events, or create provider listeners. The browser status host remains a deliberate narrow exception to workflow parity until private browser sessions and action security are implemented. Enabling it does not authorize remote exposure.

Historical [saved summaries/SMS verification](saved-summaries-sms-verification.md) passed final independent gates and guarded `0006`→`0007` editor-core activation with preservation checks; the desktop still needs relaunch. Earlier [Core Settings](core-settings-summary-verification.md), [automatic Summary/lifecycle](auto-summary-lifecycle-verification.md), [media/AI/Settings](media-ai-settings-verification.md) and [Notifications/SMS](notifications-sms-verification.md) records remain historical. Keep the existing database/profile/KWallet paths; no second summary database is introduced. The encryption revision requires the pinned SQLCipher driver, and its activation is separate from those historical checks. The running older core and live profile were not migrated by this implementation; see [encrypted history](encrypted-history.md).

Summary uses safe native scrollable Markdown, with images/embedded HTML/resources blocked and validated click-only HTTP(S) links. Saved presets, dated SQLite history and actual nullable coverage/token/latency/reuse metrics are implemented, not proposals. Retention defaults to 30 days with 7/30/90/365 preview/confirmation; pins protect entries and orphan generations are deleted only after no entry references them. Unknown legacy metrics remain null; cost/pricing remains unavailable.
